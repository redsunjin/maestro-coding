# Work Console Mockup Checklist

기준일: 2026-03-29
대상 브랜치: `codex/work-console-shell-mockup`
상태: 실행 체크리스트

## 1. 목적

이 문서는 `mockup` 브랜치에서 무엇을 검토하고 무엇을 결정해야 하는지 고정한다.

핵심 목표:

- `feature` 브랜치 구현 전에 UI 구조를 빠르게 검증한다.
- 시각 판단과 구현 판단을 섞지 않는다.
- 채택안만 `feature` 브랜치로 넘긴다.

## 2. 검토 대상

- 헤더 `Work` 버튼 위치와 활성 스타일
- 패널 폭과 여백
- 좌/우 도킹 시 시각 균형
- 세션 리스트와 현재 세션 영역 비율
- 빈 상태 문구
- 입력창 shell 배치
- `History/Repo/AutoOps`와 동시 오픈 시 겹침 정도

## 3. 결정해야 할 항목

### A. Header

- `Work` 버튼 위치가 기존 헤더 흐름을 깨지 않는가
- 활성 상태가 다른 보조 패널 버튼과 일관적인가
- `aria-controls` 연결 위치가 자연스러운가

### B. Panel Shell

- 기본 폭을 `420px`, `440px`, `460px` 중 무엇으로 둘 것인가
- 패널 헤더 액션 순서를 어떻게 둘 것인가
- 닫기 버튼과 도킹 버튼의 시선 흐름이 자연스러운가

### C. Body Layout

- 세션 리스트와 현재 세션 영역을 세로로 쌓을지, 내부 분할로 둘지
- 빈 상태에서 정보량이 과하지 않은가
- placeholder가 실제 동작으로 오해되지 않는가

### D. Narrow View

- 좁은 뷰포트에서 패널 폭이 본 화면을 과도하게 가리지 않는가
- 기존 패널과 함께 열렸을 때 최소 사용성이 유지되는가

## 4. 채택 기준

- 기존 Maestro 화면의 우선순위를 깨지 않는다.
- Work Console이 메신저처럼 보이지 않는다.
- 도킹 위치를 바꿔도 구조가 무너지지 않는다.
- 빈 상태 문구만으로도 “다음 단계 기능”임이 이해된다.

## 5. 산출물

mockup 브랜치 작업이 끝나면 아래 3개를 남긴다.

1. 채택안
2. 폐기안
3. `feature` 브랜치 반영 포인트

권장 기록 형식:

```md
## Mockup Decision
- adopted:
- rejected:
- reason:
- feature_followups:
```

## 6. 금지 항목

- 실제 세션 데이터 모델 추가
- 서버 이벤트 명세 변경
- slash command 실행 구현
- merge/approval 브리지 구현
- 테스트 통과를 위한 임시 구조 왜곡
