# Touch UX 감사·개선 — 리스크 기반 도입 로드맵 (2026-07-16)

관련 스펙: [`docs/superpowers/specs/2026-07-16-touch-ux-audit-design.md`](../specs/2026-07-16-touch-ux-audit-design.md)
대상 브랜치: `feat/touch-ux-audit`

## 원칙

- **리스크 낮은 순 = 점진 도입 순.** 순수 추가(CSS/className)부터, 로직·상태를 바꾸는 항목은 뒤로.
- **다른 세션에서 개발 작업 동시 진행 중** → `src/App.jsx`를 크게 건드리는 작업을 **가장 뒤로** 배치해
  머지 충돌을 최소화한다. 각 단계는 **독립적으로 배포/PR 가능한 단위**로 쪼갠다.
- **안전 불변**: 승인/반려/롤백 네트워크·`git merge` 로직은 어느 단계에서도 바꾸지 않는다.
- 각 단계는 자체 테스트 + `npm run qa` 통과 후 다음 단계로.

|---|---|---|---|
| 1. F1 | `src/index.css` + 각 컴포넌트 className | 없음(또는 className만) | **낮음** |

| 5. F4 | 신규 `RejectSheet.jsx` + `App.jsx` | **많음**(반려 상태·경로) | **높음** |

## 우선순위 (도입 순서)

### 1순위 — F1: 공통 "클릭감" 유틸 (리스크: 낮음 · 토대)
- `src/index.css`에 `.maestro-touch-control`(+`--compact`) 신설: `active:scale-95` + `transition`,
  `touch-manipulation`, `user-select:none`, `min 44×44px`, `:focus-visible` 링.
- 1차 컨트롤 className에 합성(색/보더/글로우 기존 유지).
- **왜 먼저**: 순수 추가 → 회귀 위험 최소, `App.jsx` 불필요, 이후 모든 단계의 시각 토대.
- **독립 배포 가능**: 예(그 자체로 체감 개선).
- 검증: 대표 컨트롤에 클래스 존재 단언, `npm run qa`.

### 2순위 — F2: 탭 타깃 44px 하한 (리스크: 낮음 · F1 후속)
- F1 클래스 적용으로 대부분 자동 해소. 명시 교정: 반려 버튼 `min-h-[32px]` → 44px+.
- 헤더·패널 잔여 소형 버튼 훑어 교정.
- **주의(검수 반영)**: 헤더는 칩·버튼이 밀집(`px-2 py-1` 다수)해 44px 일괄 강제 시 태블릿
  뷰포트에서 줄바꿈/레이아웃 붕괴 가능 → 헤더 소형 컨트롤은 `--compact` 변형을 사용하고,
  **태블릿 뷰포트(가로 1024px급) 시각 검증**을 이 단계 완료 조건에 포함한다.
- **의존**: F1. **독립 배포 가능**: 예.
- 검증: 44px 미만 잔여 없음(표본 단언) + 태블릿 뷰포트 헤더 레이아웃 확인.

### 3순위 — F3: hover 전용 조작 제거 (리스크: 낮음~중간 · 격리)
- `LaneBoard` 미리보기 아이콘 `opacity-0 group-hover` → **상시 노출**, 탭=미리보기 단서 명확화.
- 마우스 전용 `title=` 툴팁 → 상시 라벨/칩 또는 탭 확인 형태.
- **왜 여기**: 시각 변경 위주, 로직 없음, `LaneBoard`/`Header`에 격리 → `App.jsx` 무관.
- **독립 배포 가능**: 예.
- 검증: hover 없이 미리보기 어포던스 노출(DOM/클래스 단언).

### 4순위 — F5: 터치 조작 동등성 점검 (리스크: 낮음~중간 · 발견 기반)
- `useMaestroKeyboardControls` 각 단축키 ↔ 보이는 터치 컨트롤 대응 확인·보완.
- **검수 결과 파리티 대부분 기존재**: Undo 터치 버튼(`MaestroHeader` "Tap Undo"),
  숫자키↔`ProjectTabs`, Shift반려↔레인 Reject 버튼, H↔History 버튼. 확인된 핵심 갭은
  **`PreviewModal` 백드롭 탭 닫기 부재**(backdrop div에 onClick 없음) + 닫기 X 버튼 크기/hover 의존.
- `PreviewModal` 등 모달 큰 닫기 버튼 + 백드롭 탭 닫기, 패널 터치 스크롤 확인.
- **왜 여기**: 대체로 추가지만 발견되는 갭 크기가 가변 → F1~F3 이후 토대 위에서.
- 산출물: **터치 파리티 체크리스트**를 채우고 갭만 수정.
- 검증: 단축키 동작별 터치 대응 존재, 모달 터치 닫힘.

#### 터치 파리티 체크리스트 (구현 시 확인 결과)

| 단축키/동작 | 터치 대응 | 상태 |
|---|---|---|
| D/F/J/K 레인 승인 | 레인 승인 버튼 | ✅ 기존재 |
| Shift+레인키 반려 | 레인 Reject 버튼 | ✅ 기존재 |
| Ctrl+Z 롤백 | 헤더 "Tap Undo" 버튼 | ✅ 기존재 |
| 1~3 프로젝트 전환 | ProjectTabs 탭 | ✅ 기존재 |
| H 히스토리 | History 패널 토글 버튼 | ✅ 기존재 |
| Escape 패널/모달 닫기 | 각 패널 닫기 버튼(44px 적용) | ✅ 기존재 |
| Escape 미리보기 닫기 | 백드롭 탭 + 닫기 X/확인 버튼 | ✅ **이번에 추가**(백드롭 탭) |

### 5순위 — F4: 반려 사유 → 터치 시트 (리스크: 높음 · 마지막)
- 신규 `RejectSheet.jsx`(사유 칩 + 자유입력 + 큰 확인/취소, `.maestro-touch-control`).
- **참고(검수 반영)**: `Shift+레인키` 키보드 반려도 같은 `promptFeedback` 경로로 `window.prompt`를
  사용하므로, F4 완료 시 터치·키보드 양쪽 모두 시트로 통일된다.
- `src/App.jsx`의 `window.prompt` 제거 → 시트 상태 배선. 취소=반려 취소, 확인=`REJECT`(사유 300자).
- **왜 마지막**: `App.jsx` 대량 편집 → **동시 개발 세션과 충돌 위험 최고**. 다른 세션의 `App.jsx`
  작업이 정리된 뒤 착수하거나, 착수 전 리베이스로 충돌면 확인.
- **의존**: F1(시트 버튼 스타일). **독립 배포 가능**: 예(단독 PR).
- 검증: `window.prompt` 미사용, 시트 확인 시 `REJECT`+사유 전송 / 취소 시 미전송 + "REJECT CANCELED", 안전 회귀.

## 후속 스펙 (범위 밖, 본 로드맵 완료 후)

- **③ 햅틱 + 등급 피드백** → 이후 별도 스펙/로드맵.
- **① 타이밍 판정 시스템**(점수전용) → 이후 별도 스펙/로드맵.
- 두 트랙 모두 F1의 공통 press/피드백 토대 위에서 진행.

## 진행 메모

- 본 문서는 **로드맵 확정용**이며, 각 단계 착수 시 필요하면 세부 구현 계획(writing-plans)을 별도로 생성한다.
- 다른 세션 작업과의 경합 때문에 **코드 편집은 이 로드맵 합의 후** 단계별로 진행한다.
