# Maestro Operations Runbook

기준일: 2026-03-13

## 목적

이 문서는 Maestro를 "실제 프로젝트에 붙여 운영"할 때의 권장 적용 절차를 정리한다.

대상 범위:

- 로컬 또는 사내 제한망
- 단일 운영자
- 1~2개 실제 Git 레포 파일럿
- 초기 단계에서는 수동 승인 우선

비대상 범위:

- 다중 운영자 동시 사용
- 외부 공개 서비스 운영
- 자동승인 기본 ON 운영

## 권장 적용 원칙

1. 처음에는 레포 1개만 붙인다.
2. 자동승인은 처음부터 켜지 않는다.
3. 운영자는 1명으로 고정한다.
4. 레인 수는 실제 필요한 최소치만 쓴다.
5. 모든 변경은 `qa`와 스모크를 통과한 상태에서만 반영한다.

## 적용 전 결정사항

실제 적용 전에 아래 항목을 먼저 확정한다.

- 운영 대상 레포 경로
- 프로젝트 표시 이름
- 승인 레인 수 (`1~8`)
- 기본 브랜치 규칙
- 요청을 보내는 에이전트 식별자(`agentId`)
- 인증 토큰 사용 여부
- 자동승인 사용 여부

## 권장 파일럿 단계

### Phase 1. 단일 레포 수동 승인

목표:

- 승인/반려/롤백 흐름이 실제 레포에서 안정적으로 동작하는지 확인

설정:

- 레포 1개
- 레인 수 4 또는 6 중 실제 필요 수
- 자동승인 OFF
- 운영자 1명

통과 기준:

- 승인 merge 성공
- 반려 이벤트 정상 처리
- undo 정상 처리
- history 패널에서 최근 이력 확인 가능

### Phase 2. 두 번째 레포 추가

목표:

- 프로젝트 전환과 레인 설정 차이를 실운영에서 확인

설정:

- 레포 2개
- 예: alpha 4레인 / beta 6레인
- Repo 패널에서 전환

통과 기준:

- 프로젝트 전환 즉시 런타임 레포/레인 수가 바뀜
- laneIndex 6 요청이 6레인 레포에서 정상 처리됨

### Phase 3. 자동승인 검토

목표:

- 실제 반려율/undo 빈도를 보고 자동승인 필요성을 판단

권장 기준:

- 반려율이 낮고
- undo 빈도가 낮고
- 브랜치 규칙이 안정적일 때만 제한적으로 도입

## 일일 운영 시작 절차

1. 기본 검증

```bash
npm run qa
npm run smoke:lanes
```

2. 앱 실행

```bash
npm run start:app
```

3. 대시보드 확인

- `Repo` 패널에서 오늘 사용할 프로젝트 확인
- 필요하면 기존 등록 프로젝트의 레인 수 수정
- `History` 패널 정상 표시 확인
- 자동승인을 쓸 경우 `AutoOps` 상태 확인

4. 에이전트 요청 확인

가장 단순한 훅 연결:

```bash
MAESTRO_URL=http://127.0.0.1:8080 \
AGENT_ID=my-agent \
sh hooks/notify-maestro.sh
```

## 실제 운영 중 체크포인트

운영 중에는 아래를 본다.

- 특정 레인이 과도하게 몰리는지
- 반려 사유가 반복되는지
- undo가 자주 발생하는지
- lane 수가 과하거나 부족한지
- `function bach` / history / Repo 패널에서 가시성 문제가 없는지

## 권장 프로젝트 설정 표

파일럿 대상마다 아래 표를 채운다.

| 항목 | 예시 |
|---|---|
| 프로젝트 이름 | `alpha` |
| 로컬 경로 | `/Users/you/projects/alpha` |
| 레인 수 | `4` |
| 승인 방식 | `manual only` |
| 허용 브랜치 | `feature/*` |
| 운영자 | `1명` |
| 자동승인 | `OFF` |

## 장애 대응

### 1. 잘못된 레포가 활성화됨

- `Repo` 패널에서 올바른 프로젝트로 다시 전환
- 필요 시 `.env`의 `MAIN_REPO_PATH`, `MAESTRO_PROJECT_LANE_COUNT` 확인

### 2. 레인 수가 맞지 않음

- `Repo` 패널에서 `선택 프로젝트 레인 수` 수정 후 `레인 저장`
- 활성 프로젝트면 즉시 런타임에 반영됨

### 3. 승인 merge 실패

- 해당 레포 브랜치가 실제 존재하는지 확인
- 로컬 레포 상태 확인
- 필요 시 `History`에서 요청/실패 이벤트 확인

### 4. 토큰 인증 문제

- `MAESTRO_SERVER_TOKEN`과 패널 저장 토큰 일치 여부 확인
- `401`이면 `Repo` 또는 `AutoOps` 패널에서 토큰 재저장

## 파일럿 종료 후 판단 기준

아래 조건을 만족하면 다음 단계로 올린다.

- 승인/반려/undo가 최소 며칠 안정적으로 동작
- 프로젝트 전환 실수가 반복되지 않음
- 레인 수가 레포별로 안정적으로 고정
- 운영자가 패널 조작 흐름을 반복 없이 수행 가능

아래 조건이면 적용 범위를 넓히지 않는다.

- undo 빈도가 높음
- 잘못된 레포 전환이 반복됨
- branchName 규칙이 불명확함
- 자동승인 없이도 운영자가 처리량을 감당 못함
